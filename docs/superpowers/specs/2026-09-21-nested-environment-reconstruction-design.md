# 嵌套环境重建设计

## 目标

修复翻译后 LaTeX 重建阶段遗漏嵌套环境占位符的问题，避免其进入 `pdflatex` 输入并引发编译错误。

## 范围

仅修改环境占位符的重建逻辑及其回归测试。不修改 XeLaTeX 的编译顺序、`axessibility` 宏包或源论文内容。

## 方案

`LatexConstructor._revert_envs()` 每轮只替换当前文本中实际出现的环境占位符，并在本轮至少发生一次替换时继续下一轮。这样无论 `envs` 的记录顺序如何，外层环境还原后暴露出的内层占位符都会在后续轮次还原。

若一轮没有替换但文本仍含环境占位符，方法抛出 `ValueError`，在写出 `.tex` 前阻止无效文档继续进入编译阶段。若未解析占位符集合重复，则将其视为自引用或循环引用并抛出同类错误，避免无限回填。错误消息包含残留占位符，便于定位缺失或循环的环境记录。

## 验证

新增回归测试，构造外层 `itemize` 中包含多个内层 `itemize` 的环境记录，且将内层记录放在外层之前，复现当前失败顺序。测试应确认 `construct()` 写出的主文件包含完整嵌套环境，不含 `PLACEHOLDER_ENV`，并保留语言支持包注入行为。

另增加残留环境占位符测试：当节内容引用不存在于 `envs` 的环境占位符时，重建必须失败，而不能静默删除该占位符。

增加循环映射测试：两个环境占位符互相引用时，重建必须以 `ValueError` 终止而不能无限循环。
